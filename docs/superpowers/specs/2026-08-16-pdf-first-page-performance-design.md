# PDF 首屏性能优化设计

## 问题

当前 `ReaderPdf` 在加载 PDF 后，先并发渲染最多 20 个缩略图，等待全部完成后才渲染当前主页面。`renderPdfPage` 又在 Canvas 绘制前同步等待文本提取，导致首屏被缩略图和文本工作阻塞。翻页或缩放时，旧渲染也可能与新任务重叠。

## 目标

- PDF 文档加载后优先显示当前主页面。
- Canvas 绘制不等待文本提取。
- 缩略图在主页面可见后按顺序渐进加载，不与主页面争抢大量并发任务。
- 翻页、缩放和卸载时，过期任务不得覆盖最新页面状态或产生未处理异常。
- 保留页码、缩放、缩略图跳转、文本内容回传和资源释放功能。

## 设计

### 分离渲染阶段

`frontend/src/reader/pdf.ts` 将页面 Canvas 绘制与文本提取拆开：主页面先完成 `page.render()` 并立即结束可见加载状态，文本通过独立异步调用随后回传。缩略图只绘制 Canvas，不提取文本。

### 主页面优先调度

`ReaderPdf.vue` 加载文档后立即渲染当前页，不再等待缩略图。主页面完成后，通过串行队列渐进渲染最多 20 个缩略图。队列在每个缩略图之间检查组件是否仍挂载和 PDF 是否仍为当前实例。

### 过期任务保护

每次主页面渲染增加递增请求编号。只有最新编号可以更新 `busy`、可选择文本并触发 `text` 事件。组件卸载后不再写入响应式状态；已有 PDF 文档仍调用 `destroy()`，对象 URL 仍被撤销。

### 加载反馈

主页面保持明确的渲染状态；缩略图区允许稍后逐个出现。渲染错误显示安全、可重试的提示，不展示内部堆栈。

## 测试

- 先写测试证明当前实现会等待缩略图后才请求主页面。
- 验证主页面 Canvas 完成不等待文本提取。
- 验证缩略图不提取文本且串行渐进加载。
- 验证快速翻页时旧任务不能覆盖新页面文本和加载状态。
- 验证卸载仍销毁 PDF 并撤销 URL。
- 运行前端全量测试和生产构建。

## kkFileView 决策

本阶段不引入 kkFileView。它适合 Office/WPS/CAD 等通用预览，需增加独立服务、文件访问 URL 与安全配置；当前 PDF 首屏问题来自本地 PDF.js 调度，直接修复的依赖、部署和安全成本更低。

## 非目标

- 不修改上传、解析、存储和数据库。
- 不增加服务端 PDF 转图片。
- 不在本阶段实现连续滚动、多页虚拟列表或 Office 预览。
