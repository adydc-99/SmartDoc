# SmartDoc 学习与编程资料工作台设计

## 1. 产品目标

将现有“单份 PDF 摘要与问答”MVP 升级为单用户、本地优先的学习资料工作台，服务教材、论文、Java 技术文档、Markdown 和代码文件的长期阅读、摘录、笔记、检索与复习。

AI 是按需增强能力，不是产品运行前提。文件管理、阅读、搜索、笔记和复习历史在无 API Key 时仍可使用；用户主动要求摘要、解释、问答或生成复习材料时才调用 DeepSeek。

## 2. 已确定的产品边界

- 单用户本地工作台，不提供注册、找回密码和多租户管理。
- 用户在设置页填写自己的 DeepSeek API Key，项目维护者不承担调用费用。
- 第一阶段以阅读与笔记为主，AI 复习为第二阶段，向量 RAG 为第三阶段。
- 第一阶段支持 PDF、Markdown、TXT，以及 Java、XML、YAML、SQL、JavaScript、TypeScript 等文本代码文件。
- DOCX、扫描件 OCR、Ollama、多用户系统和协作编辑不进入第一阶段。
- 保留 Demo AI；真实 AI 和 Demo AI 的结果必须在界面明确区分。

## 3. 方案比较与选择

### 方案 A：阅读笔记优先（采用）

先完成资料组织、内嵌阅读、页码定位、摘录、Markdown 笔记、代码阅读和 DeepSeek 设置。它能形成稳定的日常使用闭环，同时为复习和语义检索保留接口。

### 方案 B：AI 学习功能优先（不采用）

优先开发卡片、题目和错题本，展示感更强，但阅读与笔记基础薄弱时容易成为聊天套壳。

### 方案 C：一次完成完整知识库（不采用）

同时实现 OCR、DOCX、PGVector、复习算法和多文档问答，范围过大，不利于可验证地交付。

## 4. 信息架构

应用主导航包含：

1. 工作台
2. 资料库
3. 最近阅读
4. 收藏
5. 全部笔记
6. 复习中心
7. AI 对话
8. 设置

工作台显示最近阅读、待复习卡片、最近笔记、资料统计、快速上传和全局搜索。应用启动后不再直接进入空白文档列表。

## 5. 资料库

资料库支持：

- 文件夹和子文件夹；
- 标签与收藏；
- 重命名、移动、删除；
- 批量上传；
- 列表与卡片视图；
- 按名称、类型、标签、收藏状态和更新时间筛选；
- 文件名、正文和笔记搜索；
- 最近阅读和阅读进度。

删除文档前必须展示将被一同删除的笔记、摘录、问答历史和复习数据数量。数据库删除与文件存储清理延续现有事务后补偿策略。

## 6. 阅读器

桌面端采用三栏结构：

```text
资料目录 / 页面缩略图 | 文档阅读区域 | 笔记 / AI / 文档信息
```

左栏提供章节目录、PDF 页面缩略图、文档内搜索和页码跳转；中栏提供 PDF、Markdown、文本或代码阅读；右栏提供笔记、AI 助手和文档信息三个页签。左右栏均可折叠，宽度可调整，阅读位置自动保存。

PDF 阅读器支持缩放、上一页/下一页、页码输入、适应宽度和全屏。代码阅读器支持语法高亮、行号和复制。移动端改为单栏阅读，资料目录和笔记/AI 面板通过抽屉打开，不得隐藏功能。

## 7. 摘录与笔记

用户选中文字后显示操作栏：

```text
添加摘录 | 写笔记 | AI 解释 | AI 总结 | 复制
```

笔记保存文档、页码、原文摘录、正文、标签、收藏状态和时间。点击笔记必须能返回对应文档位置。Markdown 编辑器支持标题、列表、引用、链接、行内代码、代码块和预览，并可导出 Markdown。

PDF 文本选择无法稳定定位字符范围时，第一阶段至少保存页码和摘录文本；精确坐标高亮作为增强能力，不阻塞笔记闭环。

## 8. 编程资料能力

代码文件和文档中的代码块支持：

- 语法高亮和复制；
- 解释代码；
- 逐行说明；
- 时间复杂度分析；
- 潜在问题分析；
- 使用示例生成；
- 根据知识点生成面试题；
- 将代码与解释一并保存为笔记。

第一阶段只把文本代码文件作为只读资料，不提供在线编译或执行，避免执行不可信代码。

## 9. AI 使用与成本

只有用户主动执行下列操作时调用模型：

- 生成文档或当前页摘要；
- 自由提问；
- 解释、总结所选内容；
- 解释代码或生成示例；
- 生成学习笔记、知识卡片和复习题。

普通阅读、关键词搜索、笔记、收藏和资料管理不消耗 Token。摘要、卡片和题目保存后复用；相同问题可优先展示历史结果，由用户决定是否重新生成。

AI 回答包含来源文档、页码、原文片段、模型模式和生成时间。没有足够依据时明确提示，不强行拼接无关内容。

## 10. DeepSeek 设置与密钥安全

设置页包含 API 地址、API Key、模型名、连接测试、Demo/真实 AI 模式、最大输出长度、每日调用上限和是否在本机保存 Key。

- API Key 只提交到本地后端；
- 前端响应只返回掩码，例如 `sk-****1234`；
- 默认仅保存在后端内存，重启后清空；
- 用户明确选择本机保存后，写入 Git 忽略的 `data/` 配置；
- Key 不进入日志、数据库接口响应、Git 或前端构建产物；
- 保存的 Key 至少使用操作系统可用的本机加密能力保护，不以明文文件存储；若当前环境无法安全加密，则禁用持久保存并解释原因；
- 真实 AI 请求保留连接超时、读取超时、有界线程池和调用次数限制。

## 11. 复习中心

第二阶段提供知识卡片、选择题、简答题、答案来源、基础/进阶/面试难度、错题本、掌握状态和下次复习日期。生成结果落库，重复复习不再次调用 AI。

首版复习调度采用简单状态与日期规则，不实现复杂的 SM-2 算法；积累真实使用反馈后再升级。

## 12. 搜索与 RAG 演进

第一阶段使用数据库全文/关键词方案完成文件名、正文、笔记和标签搜索，结果展示上下文与页码。

第三阶段引入：

```text
文档切块 → Embedding → PGVector → 语义召回 → DeepSeek 组织答案
```

现有 `KeywordRetriever` 继续作为无 Embedding 模式和降级方案。检索接口保持稳定，避免改动控制器和前端契约。

## 13. 视觉与交互系统

`ui-ux-pro-max` 建议采用内容优先、中高信息密度、低动效、清晰焦点和完整响应式。技能返回的紫色 Soft UI 与专业阅读工具定位不匹配，因此保留经用户确认的墨绿色体系：

```text
主色       #173F34
强调色     #3F8C70
页面背景   #F5F7F6
正文       #17231F
边框       #DDE5E1
危险色     #C24141
```

交互要求：

- 正文默认不小于 14px，长文行高不小于 1.6；
- 点击区域至少 44×44px；
- 所有图标按钮有可访问名称和 tooltip；
- Tab 顺序符合视觉顺序，键盘焦点清晰可见；
- 提供跳过导航链接和语义化 `nav/main/article`；
- 支持亮色、暗色阅读模式与减少动画；
- 动效仅用于状态反馈，150–300ms，并遵循 `prefers-reduced-motion`；
- 在 375、768、1024、1440px 宽度验证，无非必要横向滚动；
- 移动端使用抽屉和底部操作，不删除资料导航、笔记和 AI 功能。

## 15. 后端模块与数据

新增领域模块：

- `library`：文件夹、标签、收藏；
- `reader`：阅读进度、文档内搜索；
- `note`：摘录和笔记；
- `settings`：AI 配置与密钥状态；
- `review`：卡片、题目和复习记录；
- `search`：统一搜索。

预计新增表：`folder`、`document_folder`、`tag`、`document_tag`、`reading_progress`、`note`、`note_tag`、`flashcard`、`quiz_question` 和 `review_record`。AI Key 不存入普通业务表。

正式实施前先检查当前 H2/MySQL 表结构，再生成增量 SQL。SQL 只生成到 `scripts/`，不自动执行用户数据库。

## 16. 错误处理

- 不支持的文件类型、大小或编码给出具体原因；
- 解析失败保留资料记录并提供重试；
- AI 失败不影响资料和笔记，支持稍后重试；
- Key 无效、余额不足、限流和超时使用不同提示；
- 异步任务拒绝后进入明确失败状态，不长期停留处理中；
- 文档、笔记和复习数据删除保持引用完整性；
- 搜索、阅读和笔记在真实 AI 不可用时继续工作。

## 17. 测试与验收

后端测试覆盖文件夹树、标签、收藏、阅读进度、笔记归属、删除级联、Key 掩码/不泄露、调用限额、文本格式解析和搜索。集成测试覆盖上传、阅读进度、页码笔记、AI 设置、提问来源与删除链路。

前端至少覆盖路由、资料筛选、阅读位置恢复、移动端抽屉、笔记保存、设置表单和 AI 状态。生产构建必须通过；阅读器在 375、768、1024、1440px 下完成视觉与键盘检查。

## 18. 分阶段交付

### 第一阶段：可长期使用

工作台、导航、资料文件夹/标签/收藏、PDF.js 阅读器、Markdown/文本/代码阅读、阅读进度、文档内搜索、页码笔记、DeepSeek 设置、选中内容 AI 解释、摘要与问答结果复用。

### 第二阶段：学习增强

全局搜索、知识卡片、复习题、错题本、笔记导出和多文档联合问答。

### 第三阶段：高级能力

PGVector 语义检索、DOCX、OCR、流式回答、Ollama 与更完整的间隔复习算法。

## 19. 独特价值

SmartDoc 不声称训练自己的大模型。它的差异在于把文档位置、摘录、编程代码解释、学习笔记、可追溯问答和复习流程连接起来，并保证阅读与笔记不依赖 AI。用户自备 Key，成本归属清晰；Demo、关键词检索和真实 AI 可按环境降级。
