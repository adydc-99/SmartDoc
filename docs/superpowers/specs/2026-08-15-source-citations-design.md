# SmartDoc 文档问答来源引用设计

日期：2026-08-15
目标版本：校招展示版 A（试用增强）

## 1. 目标与边界

本次增强让用户在阅读器中提问后，不仅得到答案，还能看到答案使用了文档中的哪些内容，并能从引用快速回到原文。

范围限定如下：

- 文档提问（`ASK`）返回最多 8 条按相关度排序、去重后的来源。
- 界面默认展示最相关的 3 条，用户可以展开其余来源。
- PDF 来源跳转到对应页。
- TXT、Markdown 和代码文档来源定位到包含摘录的可见内容，并短暂高亮。
- 当前页总结、选区解释、代码解释等操作继续使用它们天然对应的单一来源。
- 优化 AI 侧栏的输入、加载、答案、引用、错误与移动端状态。
- 不引入向量数据库、外部检索平台或大型 RAG 框架。
- 不增加 MySQL 表或增量 SQL。

## 2. 方案选择

采用“默认 3 条、可展开至 8 条”的来源展示方式。

固定 3 条虽然简单，但可能遗漏支撑答案的次要证据；展示所有匹配切块则容易产生大量重复内容并淹没答案。最多 8 条能覆盖跨页问题，默认折叠又能保持侧栏简洁。

检索采用现有文档切块上的轻量相关度排序，不增加向量数据库。排序结果同时作为模型上下文与响应引用，避免模型看到的材料和用户看到的引用不一致。

## 3. 后端设计

### 3.1 响应模型

`AiActionResponse` 保留现有 `source` 字段，并新增 `sources` 列表。这样现有前端、缓存结果和测试仍可兼容。

每条来源包含：

- `documentId`：所属文档。
- `pageNumber`：PDF 页码；非 PDF 仍保留解析得到的页/段落页值。
- `chunkIndex`：文档内稳定切块序号，用于列表键和定位辅助。
- `text`：最多约 120 个 Unicode 码点的原文摘录。
- `relevance`：归一化后的相关度等级，取 `HIGH` 或 `RELATED`，不向用户展示虚假的精确百分比。

旧 `source` 取 `sources` 第一项；没有多来源的操作维持原行为。

### 3.2 轻量相关度排序

文档提问沿用 `selectOwnedOrdered(userId, documentId)`，确保用户级隔离。服务层对问题进行规范化和分词，然后对每个切块计算确定性分数：

1. 完整问题短语命中权重最高。
2. 去重后的有效查询词命中标题/正文；当前切块模型只有正文，因此本次仅计算正文。
3. 同一词的重复出现设置上限，避免长切块仅靠重复堆高分数。
4. 分数相同按页码、切块序号稳定排序。
5. 相邻且内容高度重复的切块去重。

中文查询除按空白和标点拆分外，还生成长度为 2 的中文字符片段，以支持没有空格的自然问题。英文词统一小写。过短的单字符和常见停用词不参与排序。

如果没有任何有效命中，回退到文档顺序中的首批切块，并将等级标记为 `RELATED`；模型仍必须在证据不足时明确说明。

最多选择 8 条来源。发送给模型的上下文仍受现有 24,000 Unicode 码点上限约束；超出上限时按相关度顺序截断，不追加未发送给模型的引用。

### 3.3 缓存行为

现有缓存记录无需变更。缓存命中时仍加载当前用户拥有的文档切块，并使用相同的确定性算法重建 `sources`。因此无需把引用 JSON 写入数据库，也不会触发 MySQL 迁移。

强制重新生成只影响模型结果，不改变相同问题和相同文档内容下的来源排序。

### 3.4 错误与安全

- 文档不存在或不属于当前用户时不返回任何引用。
- 没有可用切块时沿用现有文档无有效上下文错误。
- 摘录只来自已拥有文档，不包含 API Key、模型请求头或供应商响应元数据。
- 后端不接受客户端传入的来源对象，防止伪造引用。

## 4. 前端交互设计

### 4.1 AI 侧栏结构

侧栏按以下顺序组织：

1. 标题与关闭按钮。
2. 操作类型、问题输入和主操作按钮。
3. 提交后的加载状态。
4. 答案卡片：模型模式、缓存状态、生成时间和答案正文。
5. “参考来源”区域：默认 3 张引用卡片。
6. “查看另外 N 条”展开按钮与重新生成按钮。
7. 现有视觉识别区域，与文档问答区保持清晰分隔。

AI 请求超过 300ms 时显示明确的处理中状态，并通过 `aria-live` 播报。请求失败时在提问区附近显示可操作的错误信息，而不是只写入屏幕阅读器状态文本。

### 4.2 引用卡片

引用卡片使用原生 `button`，整张卡片可点击并支持键盘操作。卡片包含：

- 序号，如 `[1]`。
- PDF 显示“第 N 页”；其他文档显示“段落 N”。
- “高度相关”或“相关”标签。
- 约 120 字摘录，保持原文，不执行 HTML 渲染。

触控目标不少于 44×44px，焦点轮廓清晰，颜色不作为唯一状态表达。列表使用 `documentId + chunkIndex` 作为稳定键。

### 4.3 跳转和高亮

- PDF：调用现有 `changePage(pageNumber)`，关闭移动端侧栏，使目标页可见并保存进度。
- TXT：在可见文本节点中寻找摘录的稳定前缀，滚动目标容器并临时包装为 `<mark>`。
- Markdown：在安全渲染后的文本节点中寻找匹配段落，滚动对应元素并添加临时高亮类。
- 代码：优先定位包含摘录前缀的代码行，滚动并高亮相邻行。
- 若精确定位失败：滚动到文档顶部或对应页，显示“已打开来源附近，请根据摘录核对”，不制造成功假象。

临时高亮约 2 秒后移除；遵循 `prefers-reduced-motion`，不使用强制滚动动画。

### 4.4 响应式与视觉

沿用 SmartDoc 现有颜色变量、字体和阅读器结构，不另起一套视觉系统。

- 桌面宽屏：AI 侧栏保持并排 340px，引用卡片紧凑展示。
- 中小屏：侧栏为右侧抽屉，点击引用后自动关闭，避免遮挡原文。
- 375px 宽度下不产生水平滚动；操作按钮可换行但保持 44px 高度。
- 动画限定在 150–250ms 的状态过渡，并遵循已有 reduced-motion 规则。

## 5. 数据流

1. 用户在阅读器提交问题。
2. 后端验证文档所有权和问题长度。
3. 后端加载用户拥有的有序文档切块。
4. 服务层对切块评分、去重并按上下文上限选择最多 8 条。
5. 同一批切块生成模型上下文与响应 `sources`。
6. 新生成结果写入现有 `ai_result`；缓存命中则复用答案并重建引用。
7. 前端展示答案与前 3 条来源。
8. 用户展开或点击来源，阅读器跳转并高亮原文。

## 6. 测试与验收

### 后端

- ASK 对中英文问题返回稳定排序的相关来源。
- 同页相似切块去重，最多返回 8 条。
- 上下文截断后不返回未发送给模型的来源。
- 无命中时稳定回退。
- 缓存命中仍返回相同来源且不调用模型。
- 其他操作继续返回兼容的单一 `source`。
- HTTP 响应包含 `source` 与 `sources`，所有权隔离不回归。

### 前端

- 默认只显示 3 条来源，可展开和收起其余来源。
- PDF 点击来源跳转页码并保存进度。
- 文本、Markdown、代码来源定位并高亮；失败时显示诚实反馈。
- 加载、失败、缓存和重新生成状态可见且可访问。
- 移动端点击来源后关闭抽屉。
- 键盘可以聚焦并激活所有来源卡片。

### 完整验证

- 后端全量 Maven 测试。
- 前端全量 Vitest。
- Vue TypeScript 与生产构建。
- `git diff --check`、变更文件密钥扫描和 Draft PR CI。
- 以 PDF、Markdown、TXT、代码四种资料完成手动试用清单。

## 7. 明确不做

- 不接入 Elasticsearch、Milvus、Qdrant 或其他向量数据库。
- 不实现跨文档/全知识库问答。
- 不让模型自行生成不可验证的引用编号。
- 不增加聊天历史、Agent、MCP、知识图谱或检索调试后台。
- 不复制 Ragent、AnythingLLM 或 RAGFlow 的整套实现。
